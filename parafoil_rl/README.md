# Parafoil RL Training Pipeline
## Autonomous Parafoil Landing via End-to-End PPO

---

## Architecture Overview

```
┌─────────────────────────────────────────────────────────────┐
│                     Python Training Side                    │
│                                                             │
│   train_ppo.py ──► ParafoilGymEnv ──► parafoil_cpp module  │
│       │                 │                    │              │
│      SB3/PPO       Gymnasium API        pybind11 binding    │
│                                              │              │
│          ┌───────────────────────────────────┘              │
│          │          C++ Simulation Side                     │
│          ▼                                                  │
│   ParafoilEnv.cpp  ──► nineDOF_Plant.cpp                   │
│   (RL interface)        (9DOF physics)                      │
│   reset / step          computeDerivatives                  │
│   reward / obs          rk4_step                            │
└─────────────────────────────────────────────────────────────┘
```

**Design decisions:**
- C++ handles all physics (RK4 integration, 12×12 linear solve) for speed
- Python handles PPO, neural network, and all training infrastructure
- pybind11 exposes a minimal, clean API: `reset()`, `step()`, `get_observation()`
- `dt_action=0.1s` (10 physics steps per RL decision) = realistic actuation rate
- Action space: `[deltaL, deltaR]` in `[-1, 1]` (remapped to `[0, 0.94]`)
- Observation: 12-dimensional normalized vector (see `ParafoilEnv.h`)

## Build Instructions

### 1. Install Python dependencies

```bash
pip install stable-baselines3 gymnasium pybind11 numpy matplotlib
```

### 2. Copy your existing C++ plant files

```bash
# Copy your existing C++ files alongside cpp_env/ (one level up)
cp nineDOF_Plant.h   parafoil_rl/
cp nineDOF_Plant.cpp parafoil_rl/
cp nineDOF_Parameters.h parafoil_rl/
```

> **Note on `nineDOF_Transform.h`:** Your C++ plant uses `makeTransform_InertialToBody` and `makeJ`. 
> These are defined in `nineDOF_Transform.py` but must also exist as C++ functions.
> Either add a `nineDOF_Transform.h` header with the implementations inline, or add them 
> to `nineDOF_Plant.cpp`. See the "Missing Files" note below.

### 3. Build the pybind11 module

```bash
cd parafoil_rl/cpp_env
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
make -j$(nproc)
make install   # Copies parafoil_cpp.so to python_env/
```

On macOS, the output will be `parafoil_cpp.dylib` - this is normal.

### 4. Verify the build

```python
# Run from parafoil_rl/python_env/
import sys
sys.path.insert(0, ".")
import parafoil_cpp

params = parafoil_cpp.SystemParameters()
env = parafoil_cpp.ParafoilEnv(params, 0.0, 0.0)
obs = env.reset(seed=42)
print(f"Observation: {list(obs)}")
print(f"Obs size: {len(obs)}")   # Should print 12
```

## Observation Vector (12 dimensions)

| Index | Variable          | Description                         | Range     |
|-------|-------------------|-------------------------------------|-----------|
| 0     | `dx_norm`         | X distance to target / 1000m        | [-1, 1]   |
| 1     | `dy_norm`         | Y distance to target / 1000m        | [-1, 1]   |
| 2     | `alt_norm`        | Altitude / 800m                     | [0, 1]    |
| 3     | `sin(psi_p)`      | Parafoil heading sine               | [-1, 1]   |
| 4     | `cos(psi_p)`      | Parafoil heading cosine             | [-1, 1]   |
| 5     | `sin(hdg_err)`    | Heading error to target (sine)      | [-1, 1]   |
| 6     | `cos(hdg_err)`    | Heading error to target (cosine)    | [-1, 1]   |
| 7     | `speed_norm`      | Horizontal airspeed / 20 m/s        | [-1, 1]   |
| 8     | `vz_norm`         | Vertical velocity / 20 m/s          | [-1, 1]   |
| 9     | `phi_p_norm`      | Parafoil roll / π                   | [-1, 1]   |
| 10    | `theta_p_norm`    | Parafoil pitch / π                  | [-1, 1]   |
| 11    | `rp_norm`         | Parafoil yaw rate / 1 rad/s         | [-1, 1]   |

---

## Action Space (2 dimensions)

Policy outputs are in `[-1, 1]` (tanh), remapped internally to `[0, 0.94]`:

| Index | Variable  | Physical meaning           |
|-------|-----------|----------------------------|
| 0     | `deltaL`  | Left brake deflection (m)  |
| 1     | `deltaR`  | Right brake deflection (m) |

**Why two separate brakes instead of one differential?**
The parafoil uses both symmetric brake (controls glide ratio / descent rate) and 
differential brake (controls heading). A single differential action would hide this.
With two brakes, the policy can independently modulate both degrees of freedom.

## Notes and Assumptions

1. **`nineDOF_Transform.h` is missing** from your provided files. The C++ plant calls
   `makeTransform_InertialToBody()` and `makeJ()`, which are defined in `nineDOF_Transform.py`.
   You must create a C++ header version. Add to your project:
   ```cpp
   // nineDOF_Transform.h (C++ version)
   Matrix3x3 makeTransform_InertialToBody(double phi, double theta, double psi);
   Matrix3x3 makeJ(double phi, double theta, double psi);
   ```
   These functions already exist in your `nineDOF_Plant.cpp` if it was compiling before.

2. **`PMASSÇ` typo**: Your Python `systemParameters` has `PMASSÇ` (with cedilla). 
   The C++ header uses `PMASSC`. This is already corrected in the C++ `ParafoilEnv.h`.

3. **Incidence is fixed at 0.0** during RL training. The nominal incidence offset 
   (`NOM_INCIDENCE = -0.055 rad`) is still applied inside the plant. This simplifies 
   the action space to just brakes, which is standard for parafoil GNC.

4. **Static atmosphere only** for initial training. The `dynamicAtmosphere` class 
   exists in Python but is not yet exposed to C++. Add `wind_x_range` / `wind_y_range` 
   in `DomainRandomizationConfig` when you're ready to train with wind.

5. **Angle wrapping**: The C++ plant wraps angles 3,4,5,6,7,8. Your Python plant also
   wraps index 3 (phi) - the C++ version is consistent with your Python version.

```bash
# 1. Build the C++ module
cd parafoil_rl/cpp_env
mkdir build && cd build && cmake .. -DCMAKE_BUILD_TYPE=Release && make -j$(nproc) && make install

# 2. Quick smoke test (1 env, 50k steps, ~2 min)
cd ../../training
python train_ppo.py --n_envs 1 --total_steps 50_000 --run_name smoke_test

# 3. Check that episodes complete and reward is non-zero
# Then scale up:
python train_ppo.py --n_envs 8 --total_steps 2_000_000 --run_name first_real_run

# 4. Evaluate
cd ../evaluation
python evaluate_ppo.py \
    --model ../checkpoints/first_real_run/best_model \
    --n_episodes 50 --plot
```

**Expected early training behavior:**
- Episodes should terminate by ground contact (not divergence)
- Initial landing errors of 300-600m are normal
- After ~500k steps, expect errors < 200m
- After ~2M steps with good hyperparams, expect errors < 100m
